# HTML Diagram (token-efficient)

Build a self-contained HTML file whose only job is to make a system's architecture
click fast: a full-screen SVG diagram, light on prose. Iterate on the diagram
itself more than anything else. If it makes sense, make it interactive: clickable
nodes and flow chips that animate request paths.

**The final deliverable is ONE self-contained `.html` file** — but the CSS, the
generic JS, and the logo never go through your tokens; a shell step inlines them
(see Workflow).

## Reference files (read only the first)

- **`references/scaffold.html`** — the starting file: minimal, runnable, one of
  every node / edge variant, one sample flow, both cards, layout tips in comments.
  The workflow **copies** it and you edit the copy — never retype the boilerplate.
- **`references/architecture-example.html`** — a full worked diagram (20 nodes,
  6 flows). Optional; open it only if you need to see complex layout done well.
- **`references/cf-style.css`** — the Creative Force design system. **Never read,
  retype, or paste it.** The class contract below is everything you need.
- **`references/diagram.js`** — generic interactivity (flow highlight, node detail,
  panel + theme toggles). **Never read or retype it** — its contract is below.
- **`references/logo.svg`** — the CF logo, inlined into `.bar` by the assemble
  step. **Never read or retype it.** Its root `<svg>` carries `class="brand-logo"`;
  keep that class if you replace the file.

Any layout (architecture, flow / sequence, code stack) is built from the same
classes; compose the topology yourself against the contract.

## Class contract (author against these; don't invent names or read the CSS)

- Layout: `.bar`, `.stage`, `.card` / `#detail` / `#flowcap`, `.tools`.
- SVG nodes: `.node` — default card. `.node.store` — grey fill, datastores.
  `.node.gate` — blue tint + blue border, gate / decision. `.node.do` /
  `.node.edge-n` (identical) — soft-blue fill, durable objects / edge compute.
  `.node.ext` — dashed border, external systems. Inside a node: `.t` (title),
  `.m` (mono meta line), `.k` (blue kicker).
- SVG edges: `.edge` — grey arrow. `.edge.dash` — dashed (async / lazy).
  `.edge.ws` — thicker (persistent / WebSocket). `.elbl` — edge label.
- Zones: `.zone` with `.ztitle` / `.zsub`.

**Edge geometry — anchor to the rect, never eyeball.** An edge's start and end
must land on a node's border, computed from that node's `rect x,y,w,h`, not
guessed: right-mid `(x+w, y+h/2)` · left-mid `(x, y+h/2)` · top-mid `(x+w/2, y)`
· bottom-mid `(x+w/2, y+h)`. A coordinate a few px off puts the arrow tail
*inside* the box — the single most common visual bug. `verify` (the `1 / ≥1 / ≥1 / 0`
counts) only checks inlining, **not geometry**: after assembling, open the output
in a browser and eyeball every edge endpoint before calling it done.
- Extras: `.badge` — step numbers on lit edges, **auto-generated by `diagram.js`**
  in `FLOWS[key].edges` order; never author badges yourself. `.src` — small
  source caption, top-right of the stage.
- Chrome: `.chip` (flow chips), `#themeToggle`, `#panelToggle`, `.brand-logo`.

Design tokens — the only values you may reference (in `style="…"` on custom SVG
bits, e.g. marker fills). **Always `var(--…)`, never hard-coded hex** — they
already flip for dark mode:

- Ink & text: `--ink`, `--body`, `--muted`.
- Surfaces: `--bg`, `--surface`, `--surface2`; hairlines `--line`, `--line-soft`.
- Accent: `--clay` (CF blue), `--clay-soft`; secondary `--olive` / `--olive-soft`;
  extra hues `--gold`, `--blue`.
- Zones: `--zone`, `--zone-line`. Shadow: `--shadow-card`.
- Type: `--sans` (Inter, UI), `--serif` (Petrona, title), `--mono` (meta / labels).

The CF logo is the first element in `.bar`. The scaffold ships an
`<img class="brand-logo" src="logo.svg" alt="Creative Force">` marker — keep it
as-is; the assemble step replaces it with the raw `<svg class="brand-logo">` from
`references/logo.svg`, so the output has **no network dependency**. Fonts are
family names with system fallbacks; nothing to bundle.

## Workflow

You author only what is unique to this diagram — the **SVG** and the **data**
(`const DETAIL`, `const FLOWS`). Everything else comes from the scaffold.

Pick a short, descriptive **kebab-case name** for the diagram from the subject
you are asked to draw (a checkout-architecture request → `checkout-architecture`;
a login sequence → `login-flow`). Below, `<NAME>` is that name and `<REF>` is
this skill's `references/` folder. **Only one file lands in the workspace: the
final `<NAME>.html`.** The authored copy lives in a temp dir so it never clutters
the workspace.

Each step is a single short command with **no multi-line quoting** — it works
pasted into bash (Git Bash / sh), PowerShell, or cmd. Pick the line matching
the shell you actually have; if variable assignments don't stick, you are not
in bash — use the PowerShell line.

1. **Copy the scaffold into temp** (zero tokens):

   ```bash
   cp <REF>/scaffold.html "${TMPDIR:-/tmp}/<NAME>.src.html"
   ```
   ```powershell
   Copy-Item <REF>\scaffold.html "$env:TEMP\<NAME>.src.html"
   ```

2. **Edit** the temp copy — replace only what is diagram-specific: `<title>`, the `.bar`
   title / sub, the chips, the SVG body (zones / edges / labels / nodes), and the
   `DETAIL` / `FLOWS` data (swap out the sample entries). Keep the `<head>`
   dark-mode script, the logo `<img>`, the cards, and both `<script>` tags as-is.
   Style only through the classes.

3. **Assemble + verify** into the workspace — the shipped script inlines the
   stylesheet, diagram.js and logo.svg and prints four verify counts that must
   read **1 / ≥ 1 / ≥ 1 / 0**. The output `<NAME>.html` is the **only** file
   that lands in the workspace:

   ```bash
   sh <REF>/assemble.sh "${TMPDIR:-/tmp}/<NAME>.src.html" <NAME>.html
   ```
   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File <REF>\assemble.ps1 -In "$env:TEMP\<NAME>.src.html" -Out <NAME>.html
   ```

   (The PowerShell line also works verbatim from cmd.) The script refuses input
   whose markers are already consumed, with an explanatory error.

### Updating an existing diagram

A built (assembled) file is a dead end — its markers are gone, so it cannot be
re-assembled; the script refuses it. To change a diagram, edit the **authored**
temp file (`${TMPDIR:-/tmp}/<NAME>.src.html`, still containing the
`<link>`/`<script src>` lines) and re-run assemble. If that temp file was cleared
between sessions, start over from step 1 with the same `<NAME>`.

### If assembly or verify fails

**Never read or retype `cf-style.css` / `diagram.js` — manual inlining is never
the fix.** Debug in this order:

1. Wrong shell — bash-style assignments and `>` redirects fail quietly in
   PowerShell/cmd. Use the PowerShell line above.
2. "No markers" error — you pointed the script at a built file; run it on the
   authored file instead (see *Updating an existing diagram*).
3. Confirm both marker lines are verbatim in the authored file:
   `<link rel="stylesheet" href="cf-style.css">` and
   `<script src="diagram.js"></script>`.
4. Re-run the assemble script.

## Interactivity contract (what `diagram.js` binds to)

- **Flow chips**: `<button class="chip" data-flow="KEY">` inside `#chips`; each
  `KEY` is a key of `FLOWS`. A `data-flow="all"` chip resets the view. (The JS
  scopes to `#chips .chip`, so `.tools` buttons are safe.)
- **Nodes**: `<g class="node" data-k="KEY">`; each `KEY` is a key of `DETAIL`
  (`{ t, m, b }` → fills `#d-title` / `#d-meta` / `#d-body`).
- **`FLOWS[key]`** = `{ name, edges:[edge ids], nodes:[node data-k], steps:[html] }`;
  edge ids match `id=` on `.edge` paths and `data-e=` on `.elbl` labels. List
  `edges` in traversal order — the auto-generated step badges number them 1…n
  in that order.
- **Tools**: `.tools` holds `#panelToggle` (hides `#detail` / `#flowcap`) and
  `#themeToggle`.
